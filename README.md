# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some ESLint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the ESLint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and [`typescript-eslint`](https://typescript-eslint.io) in your project.

## Farmer WhatsApp order updates

WhatsApp delivery is handled by Firebase Cloud Functions in `functions/`; no WhatsApp credentials are included in the Vite app. It sends only after a farmer enables WhatsApp order updates in their profile. Reservation creation and transitions to accepted, rejected, or ready for pickup are sent as WhatsApp Business template messages. Existing in-app order notifications continue to be generated by the farmer app.

Before deployment:

1. Enable Cloud Functions and Firestore for the Firebase project and install the Firebase CLI.
2. In WhatsApp Manager, create and get approval for a utility template named `agrisathi_order_update` (or configure another name). The body must contain two text parameters in this order: product name, event label. Create approved translations matching the configured language codes `en_US`, `te`, and `hi` if those languages are offered by the template. Ensure the WhatsApp Business account has the required opt-in and messaging setup.
3. Set the function parameters `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_TEMPLATE_NAME`, `WHATSAPP_GRAPH_API_VERSION`, and `FIREBASE_DATABASE_URL` to the WhatsApp sender ID, approved template name, a currently supported Graph API version, and this project's Realtime Database URL.
4. Store the long-lived server credential as a Firebase Functions secret: `firebase functions:secrets:set WHATSAPP_ACCESS_TOKEN`.
5. Deploy only the functions with `firebase deploy --only functions` after selecting the `agrisathi-a84f8` Firebase project.

Delivery outcomes are recorded in the server-only Firestore collection `whatsappDelivery`, keyed by order and event status. API failures are logged with an error code and HTTP status, without logging the recipient or access token. A status event is claimed before sending so Firebase event retries do not result in another API request. Failed sends are not automatically retried, because the provider may have accepted a request even when its response was lost; the regular in-app notification flow does not depend on WhatsApp delivery.
